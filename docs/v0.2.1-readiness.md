# v0.2.1 release-owner handoff

Status: **release preparation**. This is a patch release for the merged Base
1.10.0 ecosystem alignment. It must not be tagged or published until the
release PR is merged and the exact post-merge compatibility evidence passes.

- base-demo `0.2.1` (the final tag target is supplied only after merge);

  `167947add351b8d609b5ab17342425e9a337acbb`, installer checksum
  `94840a0e37b993065781fac3efa86ed692f974917d57a77170dae29efff539ca`;

The tracked BOM uses the reviewed pre-tag main commit as a valid self-commit
placeholder and keeps all results `not_tested`. The tag workflow rewrites only
the external BOM and installer asset to the exact annotated-tag target.

## Release gate

Before merge, require the normal pull-request checks, including the stable and
extended v1.10 scenario lanes, Ubuntu validation, macOS full validation, and
the source-provider and security checks. After merge, record the exact full
`main` commit and the successful `tests.yml` run that covers `validate` on
`macos-14`, `validate-ubuntu` on `ubuntu-24.04`, and
`validate-base-cli-source`.

Then create an annotated `v0.2.1` tag from that clean merge commit. The tag
workflow must finalize and verify `release-bom.json`, `install.sh`, and both
checksum manifests before GitHub Release publication. Verify the public
artifacts independently after publication.

The README Quick Start remains on the prior verified v0.2.0 asset until the
new v0.2.1 installer has been published and its checksum is known. Follow-up
documentation must update that URL, checksum, Base version, and demo version
together; never point users at an unpublished asset.
